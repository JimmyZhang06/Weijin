# 后端实现约束

本文件是后续实施的检查清单。MUST 为必须满足；SHOULD 为默认方案，有变更时在计划中记录原因。用户后续明确调整范围时应同步更新文档。

## A. 产品范围

- MUST：首版实现正文、日记/未寄出的信、另一视角、场景边界分支。
- MUST：新内容先为草稿，用户接受后进入正史；用户解锁不等于接受新事实。
- MUST：保留作者控制权，支持编辑、拒绝、停止生成和保留旧分支。
- MUST NOT：引入 AI 生图、语音、开放角色市场、支付系统、微服务、分支合并作为首版依赖。
- MUST NOT：把无限 Agent 对话、24 小时自治、自动改代码或“模型会自行越来越聪明”写成已实现能力。
- SHOULD：先本地单用户演示，但领域模型从第一天带所有权；生产认证上线前完成。

## B. 故事正确性

- MUST：分开世界事实、角色信念、读者可见内容和生成提案。
- MUST：上下文访问在代码中裁剪。只在 system prompt 写“不要剧透”不算隔离。
- MUST：锁定事实带来源，模型不能解锁、删除或覆盖。
- MUST：角色的认知具有故事时间和来源；谎言/猜测不自动成为正史。
- MUST：档案引用被冻结的事实，禁止解锁时随机重写历史。
- MUST：多视角保持同一事件硬事实不变；不足信息提示用户确认。
- MUST：所有正史写入是新修订；历史编辑走分支，禁止更新旧正文原地覆盖。
- MUST：首版不把连贯性模型的“通过”当成正确性保证；程序规则与人工评估并用。
- MUST：不宣称 100% 不跑设定。展示草稿与冲突，支持用户纠正。

## C. 任务和数据

- MUST：任务和节点结果持久化，worker 断电后可恢复；不能使用 API 进程内线程承载长任务。
- MUST：租约含 fencing token，过期 worker 不能写入晚到结果。
- MUST：模型调用期间不持有长数据库事务或行锁。
- MUST：任务创建幂等、接受草稿幂等；条件更新保护 branch head。
- MUST：并发草稿不能最后写入者覆盖；显式返回版本冲突。
- MUST：任务重试、节点修复、网络超时均受全局预算约束。
- MUST：取消会阻止新调用和正史写入，但实际已发生费用仍入账。
- MUST：删除世界后禁止 worker 回写；清理检查世界 tombstone 和租约。
- MUST：每个模型调用保存配置与 prompt 版本，不能把随机生成复现等同于检查点恢复。

## D. 信息与内容处理

- MUST：所有 world/branch/draft/job/artifact 查询校验所有权及关联归属，包含 SSE 和导出。
- MUST：读者模式在服务端隐藏未解锁正文、秘密标题和调试元信息。
- MUST：故事正文和导入材料视为不可信数据，不能被当作系统指令执行。
- MUST：模型没有任意 SQL、shell、网页请求或文件访问工具。未来增加工具需要重新界定能力。
- MUST：密钥只在服务端配置，禁止写入仓库、日志、错误响应和提示词。
- MUST：默认日志仅含 ID、状态、耗时、用量，不记录正文或模型原始上下文。
- MUST：输出按文本/受控 Markdown 渲染，禁止原样执行 HTML/脚本；链接另行验证。
- MUST：真实用户内容不会在未说明和授权的情况下用于跨用户训练或公共示例。
- MUST：初始演示/评估使用自建原创材料；不打包未经授权的小说全文作为项目数据。
- SHOULD：生产正文与草稿默认保留至用户删除；节点原始上下文默认不落库，临时脱敏调试留存不超过 7 天。
- MUST：删除立即撤销访问，在线主存储清理目标 24 小时；备份轮换初值 30 天，并在恢复后重新应用删除记录。上线前验证并公开实际规则。
- MUST：上线前明确模型服务的数据处理配置、内容边界和用户删除路径；不把供应商会话保留行为默认为零。

## E. 工程交付

- MUST：迁移可从空 PostgreSQL 应用；破坏性迁移需单独说明数据影响与回滚/恢复方案。
- MUST：类型化 schema、错误码、OpenAPI 与运行状态保持一致。
- MUST：领域测试默认 mock 模型，不消耗付费 API；真实模型评估单独标记并设置预算。
- MUST：数据库并发、租约和恢复用真实 PostgreSQL 测试，不能用 SQLite 测试结果替代。
- MUST：依赖锁定，无凭据的 .env.example，启动说明适配 Windows 工作区 + Linux 容器。
- MUST：每阶段交付可运行闭环和对应验证证据；计划中的目标不得写成已通过结果。
- SHOULD：没有明确指标证明必要时，不增加框架、独立队列、向量库或多个数据库。

## F. 超出首版的升级触发条件

| 升级项 | 需要先证明 |
| --- | --- |
| LangGraph/外部工作流框架 | 自有状态机难以维护的实际分支/恢复复杂度 |
| 专用消息队列 | 数据库领取延迟/吞吐已成为瓶颈 |
| 向量检索 | 结构化召回在长篇评估中存在稳定遗漏 |
| 自动连载 | 手动创作有稳定复用、低废稿率、明确用户上限与停止条件 |
| 自动接受草稿 | 用户明确启用，并有可回退记录与重大事件拦截机制 |
| 多人共享 | 具备独立权限、版本冲突和剧透控制设计 |
