# M1：写作工作台整改

日期：2026-09-10。状态：M1 已实施；仍为本地模板模式，未接入真实模型。

## 检测结论

- 旧首页和阅读页主要展示固定车站模板，不能承载完整写作流程。
- 创建只有两个人物和开场，缺少原创/同人区分、原作时间点、关系、AU/偏离和禁改设定。
- 没有章纲、手写正文、修改草稿、历史修订入口；只能接受/拒绝生成稿。
- 后台已有任务节点、不可变修订、知识边界，但前端没有展示证据。
- mock 的审校节点固定 passed=true，容易与真实语义审校混淆。整改为真实结构校验，清楚标明未做语义审校。

## 本轮实施范围

1. 重构为文学编辑工作台：深墨色导航、纸张正文、细线分隔和少量铜金色强调。主要版面服务编辑，不用插画填充。
2. 作品档案：原创/同人、原作及时间点、人物关系、偏离原作、写作边界、叙事偏好。空值不臆造原作知识。
3. 章节计划：独立标题、场景目标、目标字数，章纲不会被当作已发生事实。
4. 正文可手写，保存为草稿，刷新可恢复，显式定稿才成为新修订；编辑旧稿不直接覆盖历史。
5. 已定稿章节可创建修订草稿；改写后标记所依赖的番外需复核，后续章节存在时要求先开分支。
6. 右侧展示实际保存版本、角色信息边界、后台节点/用量与结构检查，不展示伪造 Agent 对话或评分。
7. 保留私密档案、多视角和故事分支，但次于作品设定—章纲—写作—修订主线。

## 后端变更原则

- 现有世界无损兼容，通过快照缺省字段读取 brief/chapter_plans。
- 世界设定修改产生新 revision，锁定人物特点修改必须显式确认。
- 手写草稿使用任务记录与草稿版本号，模型调用数为零。
- PATCH 草稿使用 expected_version，定稿使用 expected_content_hash，防止多标签页覆盖。
- 接受请求兼容旧调用，但已修改草稿要求内容 hash；内容语义变化由作者确认，不伪装成已自动同步事实。
- 不接入未授权或未配置的付费模型，不把 mock 节点包装成真正自治集群。

## 验收目标

- 创建同人作品并保存原作锚点、AU、边界；刷新后仍在。
- 保存章纲后手写章节，刷新恢复草稿、定稿、修订最后一章、检查历史版本。
- 草稿版本冲突和定稿内容冲突明确阻止覆盖。
- 模板生成的章节绑定章纲，实际节点可读取；前端始终说明模型尚未接入。
- 已定稿内容不因配置修改被原地改写；分支保持独立。
- 桌面与窄屏完成主要操作，文本安全呈现，编辑未保存时离开有保护。

## 暂不解决

真实模型中文文笔、原作自动检索、长篇语义一致性、完整角色工具调用、多人协作、公开发布、全文自动重写均非本轮交付承诺。

## 实施与验收结果

- 前端已替换为作品集、章节导航、正文编辑、设定与章纲、角色旁页、上下文/执行/版本三类检查面板。保留既有作品数据。
- 后端新增 workspace、manual-drafts、草稿 PATCH、history、job trace 接口；迁移 0002 增加草稿版本号，开发和测试库均已应用。
- 独立测试库 14 项集成测试通过，覆盖既有生成/分支流程及新设定锁定、版本和内容冲突、末章修订与旁页失效、权限隔离。Ruff、前端格式与 JS 语法检查通过。
- 浏览器创建独立作品“余信 · 写作验收”，验证同人锚点/边界/章纲保存、手写草稿、重新加载恢复、确认定稿及真实版本历史。未修改原有“春夏”等作品。
- 已检查桌面和 390px 窄屏，手机无横向溢出、章节导航可使用，正文连续显示；浏览器未记录 JS 错误。
- 后台模板输出仍不能理解任意原作与开场。检查仅验证结构和引用；新增正文事实没有自动提取到人物认知中，后续必须实现事实提案与作者核对流程。
- 当前仍是两名既有人物、纯文本编辑、末章修订；较早章节需开新路线。历史面板列出版本元数据，尚无逐字差异与恢复操作。
