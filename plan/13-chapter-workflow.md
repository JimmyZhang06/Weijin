# 章节工作流梳理与实施

## 产品主线
作品 → 章节 → 当前稿 → 作者确认定稿 → 下一章。手写、对话改稿与批量生成共享章节导航。章节计划是可选的创作意图，不应是开始落笔的门槛。

## 本轮已落地
- 创建作品后直接进入正文。目录加号与“继续下一章”共用入口，优先选择尚未写作、没有待审阅稿的章纲。
- 目录先排列已定稿正文，再显示未写章纲和草稿。通过后端返回的 draft_kind、draft_plan_id、replace_scene_id 绑定章节，不通过标题猜测归属。
- 对应章节显示“构思中 / 草稿待审阅 / 已定稿 / 有修订稿”。同章多份草稿保留备选入口；旧正文仍可打开。旁页草稿不混入正文章节。
- 对话发送前保存当前正文，并保留选段作为本次请求输入。设定未保存时给出明确说明，避免保存设定导致草稿基线静默变化。生成新章模式遇到已有正文时转为修改当前稿。
- 定稿后停留在完成的正文，不自动跳到其他待定稿。提供继续下一章。
- 全 AI 任务的进度及未导入章节同步显示在目录，可直接送入编辑器审阅。保持顺序采用及作者定稿约束。
- 正文隐藏固定模板起稿入口；上下文说明明确最近三章的记忆范围。
- 非末章不再显示不可用的“修订本章”，显示“从本章另写”，保留现有后端保护。

## 约束与后续阶段
- 当前仍为手动保存到数据库，另有发送对话前保存；不宣称已实现持续自动保存。后台自动保存需要覆盖输入期间保存、切换章节、离线恢复及多窗口冲突后再开放。
- 不解除旧章的分支限制。后续普通修订需要重建后文的分支锚点语义、明确连续性待核对状态，不能只删除校验条件。
- 新作品的两人物表单尚未简化，受到后端角色数量约束；尚未实现记住最后编辑位置。
- 批量写作不会自动定稿；未生成章节打开任务详情，已生成章节通过原有导入接口顺序采用。任务失败不会自动重复付费调用。
- 草稿采用仍要求版本一致。修改作品设定可能使旧稿需要重新处理，本轮没有自动合并冲突。
- 不修改用户的春夏、白夜作品；交互验收只使用“余信 · 写作验收”。

## 验证
- PostgreSQL 集成测试 30 项通过；无真实模型付费调用。
- 实际浏览器完成：继续下一章 → 手写 → 保存 → 章节目录找回 → 定稿 → 留在完成章节。
- 检查桌面与 390px 手机宽度，修正面包屑短标签换行；新增按钮无横向页面溢出。

## 2026-09-11 连续写作解锁修复
- 实际原因：原始导入稿已搁置，作者定稿的是通过 revise/draft_id 创建的派生稿。原实现只检查原始稿 accepted_revision_id。
- 在同一分支中沿显式修改关系查找已定稿后代。不会按标题猜测；仍要求当前版本与该定稿版本一致。拆分“前章未定稿”与“作品版本随后变化”的错误说明。
- 31 项集成测试通过，新增原稿搁置、派生稿定稿后第二章可导入的回归测试。
- 使用隔离测试数据库和 8766 测试服务，在真实浏览器完成第二章打开、定稿、刷新验证；模型输出使用确定性替身，无付费测试请求。
- 对正式白夜作品只读确认派生稿能解析且定稿版本与当前版本相符，没有修改正文。
- 修复书架加载失败时显示 0 本作品的问题：改为持续错误说明和重新加载按钮。
