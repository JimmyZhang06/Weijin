# 开发阶段与验收

状态：已开始执行。P0 核心及 P1～P3 的 mock 流程子集已实现，详见 `08-implementation-status.md`。以下工作量为最初粗估，不代表剩余工期，也不作为交付承诺。

## P0：基础骨架与接口冻结（约 2～3 个工作日）

- 检查 Python/uv/Docker/WSL2；核验并锁定依赖版本。
- 创建 FastAPI、worker、PostgreSQL Compose、配置和迁移骨架。
- 实现 mock 模型协议和固定原创故事样本。
- 冻结 job/draft/revision 状态和统一错误格式。

验收：一份启动说明能在空环境启动；健康检查分别报告 API、数据库与 worker 心跳；无 API key 可运行 mock；生产模式拒绝开发身份配置。

## P1：领域与版本正确性（约 4～6 个工作日）

- 世界、人物、修订快照、事实、认知、秘密、关系。
- 创建/接受设定草稿、正文版本、分支读取与 fork。
- 所有权和 reader/author 服务端投影。

验收：分支只继承锚点以前内容；历史不可变；角色上下文没有未知秘密；过期 expected_revision 被拒绝；另一个用户不能读取任何关联资源。

## P2：可靠任务与正文闭环（约 4～6 个工作日）

- 任务表、租约、fencing、节点结果、重试、取消、预算和用量账本。
- mock 跑通导演→角色→裁决→正文→校验→草稿→接受。
- SSE 重连与任务查询；用户编辑产生差异草稿。

验收：生成期间重启 worker 可恢复；同幂等键只产生一个任务；过期 worker 不能提交；两个并发草稿只允许一个接受；客户端断线不会丢结果。

## P3：产品亮点闭环（约 3～5 个工作日）

- 未寄出的信、日记和另一视角生成。
- 档案接受与解锁分离；揭示缓存、阅读进度和失效处理。
- 修改关键场景生成新分支；导出 Markdown。

验收演示：两名角色发生误会 → 阅读正文 → 解锁未寄出的信 → 阅读另一视角 → 分支改变动作 → 新正文遵循新状态、原稿不变。

## P4：真实模型和质量评估（约 4～7 个工作日）

- 选择一个供应商完成适配与能力测试，再决定是否添加第二供应商。
- 校准上下文、长度、并发、费用和延迟；补充价格来源及生效日期。
- 对照同模型单次提示基线，进行盲评；根据失败样本修改流程。

验收：真实调用不会突破预算；输出不合法可以有界失败；评估报告包含样本数、原始指标、失败例和局限。不能仅展示挑选后的成功样例。

## P5：小范围试用准备（约 3～5 个工作日）

- 接入正式认证、速率限制、数据删除、备份恢复与可观测性。
- 生产部署配置及密钥管理；前后端联调。
- 招募已有原创角色的用户，观察真实续写行为。

验收：端到端越权/剧透测试、删除后任务回写测试、备份恢复演练通过；用户能发现错误并修正；记录第二次使用和付费意向，不能把意向等同收入。

## 自动化关键用例

| 用例 | 必须满足的结果 |
| --- | --- |
| 信被截走，A 不知道 | A 的输入无真实秘密，认知保留误解 |
| A 撒谎 | 对白不自动升级为世界事实 |
| 过去视角 | 不包含人物后来才获得的知识 |
| 同一场景另一视角 | 对白、物品、时间等硬事实一致 |
| 解锁两次 | 返回同一内容版本，不创建新模型任务 |
| 档案包含新关键事实 | 阻断并请求用户确认，不静默加入 |
| 分支从第二幕前建立 | 无第三幕后父分支事实、摘要和档案 |
| 锁定事实被生成覆盖 | 校验失败，head 不变 |
| 双任务同时接受 | 一个成功，一个 REVISION_CONFLICT |
| worker 在节点保存后崩溃 | 成功节点复用，不重复写业务结果 |
| 调用成功但结果未保存时崩溃 | 可恢复，明确用量不确定，不承诺免费重试 |
| 过期租约晚到响应 | fencing 拒绝结果 |
| 取消与完成竞争 | 唯一终态，不再调度下一节点 |
| 429 重试与超预算 | 退避且最终有界停止 |
| 重连 SSE | 无丢失持久阶段事件，重复可去重 |
| 未解锁秘密 | API、SSE、标题、导出均不泄露 |
| 删除运行中的世界 | 立即无法访问，worker 不能回写 |
| 文本包含伪系统指令 | 无工具执行，无权限或上下文范围变化 |

## 质量与产品验证

建立至少 20 个原创短篇测试场景，覆盖误会、秘密、回忆、多视角、锁定关系和分支。真实模型对照评估每个样本运行至少 3 次；所有运行纳入报告。

硬规则测试目标为全部通过，失败即阻断阶段。以下软指标仅是首轮建议门槛：

- 双人盲评比较人物一致性、因果连续性、文字可读性和额外内容价值，报告分歧。
- 每个样本记录严重矛盾次数和人工修改量；目标是比同模型单次提示基线减少修正负担。没有优势则简化 Agent 流程。
- 记录正文/档案 p50/p95 完成时长、模型调用数、token、失败率和实际成本；质量目标与延迟共同评估。
- 首轮至少邀请 5 名目标用户完成自带角色创作，观察 7 天内是否主动续写、是否探索档案/视角、是否保留分支。不把小样本结果推广为市场证明。
- 收集是否愿意付费及具体原因；后续真实收费试点另行设计，不在首版接入支付。

## 成本账本与上线门槛

单任务模型成本 = Σ（实际输入 token × 版本化输入单价 + 实际输出 token × 输出单价），根据供应商补充缓存等计费项。重复请求、修复、失败调用均计入；未知费用单列。

产品成本还包括托管、存储、人工支持和退款，不能只用 token 费用估算利润。未获得实际运行数据前不决定无限量套餐和固定毛利目标。

上线必须具备：可追踪版本、所有权隔离、恢复能力、预算硬限、取消、删除、错误反馈和真实模型评估报告。付费验证与技术上线分别记录。
