## 综合范围

产品主线：我的故事 → 人物与开场 → 待确认正文 → 收进故事 → 私密档案/另一视角 → 接受与解锁 → 场景边界分支 → 返回原稿。

此次执行目标为 **M0：连接真实数据库的前后端流程原型**。先覆盖 P0 和 P1 核心子集，提前实现部分 P2/P3 的固定模板流程以验证体验。未宣称完整完成所有阶段。

## 实际技术路径与原计划差异

- 后端采用 Python 3.12 + FastAPI + SQLAlchemy + Alembic + PostgreSQL + 独立 worker，uv.lock 已生成。
- 本机 Docker 可用，数据库使用版本固定的 postgres:16.6-alpine3.20；未做生产镜像安全评估。
- API/worker 当前运行于本机虚拟环境，Compose 仅运行数据库；全容器部署待办。
- 前端先使用原生 HTML/CSS/JS，由 API 同源提供，减少早期构建依赖。阅读、草稿、分支使用实际 API，不是纯静态演示。
- 首版事实、认知、人物、正文和档案存不可变 JSONB 快照，独立结构化投影表推迟。快照带 hash，数据库阻止 UPDATE 修订。
- 创建世界时直接接受用户填写的初始人物设定；后续人物修改草稿尚未实现。
- 前端通过任务轮询恢复结果，后端 SSE 已提供并测试；客户端 SSE 接入后续实施。
- 档案 reveal 路径带 branch_id，避免跨分支歧义；增加 branch/jobs 列表支持刷新找回任务。
- 模型适配目前只有 mock 协议与固定模板，不运行多个真实模型。模板不遵循任意开场/指令，UI 明确告知。
- 真实模型预算、调用重试、并发心跳和未知费用账本尚未实现；配置显式拒绝非 mock provider，避免误用。

## 已知限制

- 角色秘密裁剪通过结构测试，但正文作者只是模板，未验证真实模型的语义泄露和人物一致性。
- 无完整 reader/author 权限系统；当前所有操作属于同一本机作者。reader 投影隐藏事实和未解锁档案正文；专用作者草稿与上下文接口仍允许作者检查自己的材料。
- 阅读进度通过用户打开档案时确认当前已呈现场景，未实现逐段可视位置追踪。
- 解锁不改变修订；接受档案会改变修订，因此同基线其他草稿可能发生冲突，这是预期行为。
- 没有编辑已有正文或迁移旧草稿到新分支的 UI；冲突时保留稿件并提示，后续补齐操作。
- 深色主题、复杂分支图、故事删除、真实额度显示、移动端全面验收仍待办。
- 当前 API 使用本地固定身份，不能当作部署版。

1. P1 补齐设定编辑草稿、锁定变更和可观测事件模型，定义角色可见观察如何进入上下文。

3. 为外部模型实现调用预算、超时、调用级账本、heartbeat 与恢复；再接一个真实供应商。
4. 用真实人物材料盲评正文/档案/视角，决定是否保留更多 Agent 节点。
5. 前端深化阅读、待确认状态、错误恢复和编辑器，然后推进生产准备。
