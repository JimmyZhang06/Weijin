# 生成工作流与运行控制

## 1. 通用运行状态

```text
queued → running → succeeded（产生草稿）
                 → needs_input
                 → failed
                 → cancelled
                 → budget_exceeded
```

网络重试由 running 的节点 attempt/next_attempt_at 管理。needs_input 为终止等待状态，恢复使用带用户补充的新任务和新预算；不让 worker 占着租约等待用户。

succeeded 不代表正史已改变。draft 独立状态为 pending、accepted、rejected、stale；接受由独立业务事务执行。

## 2. 正文生成

1. **读取冻结输入**：固定 base_revision、人物、用户目标、模型和 prompt 配置。
2. **预算与确定性预检**：检查世界归属、输入长度、锁定规则、上下文容量。
3. **导演计划**：输出场景目标、参与者、候选冲突、允许揭示的事实 ID、停止条件。
4. **角色提案**：最多 3 名相关角色，使用各自可见上下文，输出可观察行为、对白、动机摘要和引用 ID。角色可提案但不能自行写入事实。
5. **导演裁决**：选择相容行为，形成有序事件和 proposed_delta；模型不得要求永久自由循环。
6. **作者成文**：根据裁决后的事件写统一风格正文。作者可见全局材料，但受到叙事视角和剧透限制。
7. **校验**：schema、引用、时间、锁定项、认知来源、分支归属由程序检查；语义矛盾和人物一致性由审校模型辅助判断。
8. **最多一次定向修复**：只针对报告中的问题修复，之后再次校验。仍有阻断问题返回 needs_input，不强行通过。
9. **草稿落库**：正文、事实差异、校验报告及来源入库，等待用户接受。

导演与审校知道秘密，不能让它们的全部输出进入角色上下文。导演传给角色的是经过程序投影的公共指令，不能转发全局思考或包含秘密的计划。

## 3. 档案生成

输入：accepted revision、scene anchor、character_id、diary/unsent_letter。

构建该人物在锚点的认知 → 生成档案 → 校验认知与事实引用 → 草稿 → 用户接受 → 满足阅读条件时解锁。

缓存键含 owner/world、branch、base_revision、anchor、人物、类型、prompt 版本和输入 hash。仅返回完全相同输入下已保存的版本，显式 regenerate 才创建新草稿。缓存不能跨用户或分支泄露内容。

## 4. 另一视角

读取原场景已确认的事件顺序和人物在该时刻的位置、认知。生成另一视角时，同一对白、物品归属、出入时间等硬事实必须一致。

允许叙述已确认但原正文未展示的行为，不允许逆改原事件。如果材料不足以支持新视角，提出具体待确认问题，不能靠全知叙事填补漏洞。

## 5. 上下文构建

优先级：锁定设定 → 当前场景必要事实 → 角色认知 → 相关事件 → 已验证摘要 → 最近正文。

先按 world/branch/revision/time/visibility 做数据库过滤，再按相关性挑选；不能先全局向量检索后只依赖提示词过滤。

摘要是可重建的辅助材料，带 revision/hash；不能成为事实唯一来源。必要事实超出上下文时拆分任务或返回 CONTEXT_TOO_LARGE，不截掉锁定规则继续运行。

首版不用向量数据库，采用结构化关联和受限文本检索。只有上下文召回评估发现明确瓶颈时再考虑向量检索。

## 6. 初始运行上限（待基准测试调整）

| 项目 | 默认上限 |
| --- | --- |
| 单次场景输出 | 约 800～1500 汉字目标，适配器另设硬输出 token 上限 |
| 正文任务总模型调用 | 12 次，含失败重试和修复 |
| 档案/另一视角任务总调用 | 4 次，含重试和修复 |
| 每调用连接/响应超时 | 10 秒 / 120 秒，供应商适配时核验 |
| 单任务总运行时间 | 10 分钟 |
| 总输入 token 预算 | 正文初值 60,000；档案 15,000，累计所有调用 |
| 总输出 token 预算 | 正文初值 12,000；档案 4,000 |
| 单用户活动任务 | 2 个；先到先服务 |
| 工作进程内模型并发 | 初值 2，另受供应商速率限制 |

汉字数与 token 数不等价。费用上限由版本化单价表计算并由产品配置提供；价格缺失时禁止有收费承诺的生产调用。限额数值属于保护性初值，不是性能或成本承诺。

## 7. 取消、失败、费用

- 每个节点开始前检查取消、租约和剩余预算。收到取消时尽可能关闭上游请求，但不承诺供应商停止计费。
- 取消后不接受晚到结果，不再启动节点；已产生的调用用量仍记录。取消与完成并发时由状态条件更新决定唯一结果。
- 可重试：429、部分 5xx、明确可恢复网络错误，指数退避加抖动，每节点最多额外 2 次且受全局预算限制。
- 不重试：鉴权失败、不支持的模型能力、输入越界、领域冲突。输出不合法走一次专门修复，不无限重试。
- 预留调用最坏允许成本，实际用量返回后结算；未知用量暂保留预留额，人工/供应商核对后调整，不能立即全额释放。
- 使用内部调用 ID 去重用量账本；实际重复上游调用各自记账，不能因业务幂等而忽略成本。

## 8. 流式预览

SSE 只发阶段、字数进度、允许查看的草稿片段和最终草稿 ID。预览清楚标记未审核，不进入正史。

读者模式不接收未经审校的文本增量；只在通过可见性检查后读取内容。作者模式可看自己草稿预览，但不能访问其他世界。

调试不保存或展示模型隐藏推理。仅存结构化行动、引用 ID、简短可审核理由、用量和节点结果。
