# M3：写作室重设计与全 AI 写作

## 产品目标与界面

沿用已认可的 design-review 浅暖灰 / 石墨黑方向，实际应用入口为 `/`。`concept/` 和 `design-review/` 仍为历史静态参考，不是生产功能入口。

- 主工作台：章节导航、正文、创作对话三栏。取消正文上方重复的大作品标题；保留有实际用途的作品工具导航。
- 正文默认 17px 无衬线、约 2 倍行距，标题使用衬线。支持大字号、专注模式、浅深主题，主题偏好本机保存。
- 有已保存章纲时，正文显示可展开的「本章创作意图」。无章纲时不编造提示。
- 「撤销未保存修改」恢复当前稿最近保存内容，不冒充跨版本撤销。定稿仍产生独立历史修订。
- 全 AI 写作有独立页面：创作要求 → 篇幅 → 开始 → 章纲和逐章进度 → 阅读 / 导出 / 送入编辑器。
- 所有新按钮接真实 API；未配置模型时明确禁用开始，不展示假进度。

## 本轮实现

后端新增 `app/autowrite.py`。使用已有 PostgreSQL Job / Step / ModelCall，不新增表或队列。父任务持久化子任务列表，每个子任务最多发出一次模型调用。

1. 作者先建立作品与人物，保存原作锚点、文风和边界；在全 AI 写作页填写本轮目标。
2. 创建父任务，冻结故事 revision、模型、单次输出 token 上限、超时及篇幅。
3. worker 协调器先创建章纲子任务，通过 Responses 严格 JSON schema 返回指定数量的章节。
4. 前一步成功后创建下一章子任务。每章使用完整本轮章纲、最近三章已定稿正文、最近三章本轮初稿及公开人物设定。
5. 每章结果单独持久化，父任务在刷新 / API 重启 / worker 重启后继续可查。已完成调用不重新付费生成。
6. 初稿可按已完成章节导出 Markdown。按顺序送入编辑器形成真正待审阅草稿，逐章人工定稿后进入正文。

## 状态与约束

- 父任务状态：orchestrating / paused / succeeded / failed / cancelled。
- 首版每轮 1–8 章、每章目标 300–2500 字；前端提供常用篇幅。总模型调用硬上限为章节数 + 1；每次输出 token 上限继承服务端配置。实际字数不保证精确。
- 这是有界初稿生成，不是无限自动连载。用户本次请求授权增加该功能；不自动接受草稿，不自动更新世界事实。
- 「本章后暂停」允许已提交的当前子任务完成，不派发下一步；「继续写作」恢复调度。「立即停止」取消排队 / 执行中的子任务，fencing token 防止晚到稿件写入。
- 失败 / 超时 / 结果不明后停下，不自动重新请求。可能发生的用量按已有 ModelCall 机制记录；未知费用不显示为零费用。
- 采用第 N 章前必须完成前 N-1 章定稿；新草稿必须基于父任务原始 revision 或上一章采用后的 revision。若作者改变设定或另写了正文，不允许盲目覆盖。
- 输出属于独立初稿；原作信息未核实，语义一致性未自动审校，不展示虚构的「角色一致性通过」。只提供有限上下文，不声称具备全长篇记忆。
- 暂停 / 停止 / 读取 / 送审检查所有权；创建与送审幂等。模型输入输出以文本呈现。
- 旧的单章对话不展示批量任务内部消息。模板旁页仍为模板，不宣称 AI 日记已完成。
- 全 AI 开始后会向 OpenAI 发送该作品的公开创作上下文，角色私密知识不自动发送。密钥只在 backend/.env。

## 验证与已知限制

- PostgreSQL 集成测试：24 passed，1 项第三方依赖弃用提醒。新增覆盖连续成文、承接前稿、暂停恢复、顺序采用、幂等、取消晚到结果、失败不重试、模型未配置、跨作者访问。
- CUA 实际页面检查：浅深主题、桌面三栏与窄屏折叠、撤销临时编辑、专注模式、未配置模型禁用开始。未修改用户既有正文。
- 本机未配置 OPENAI_API_KEY / OPENAI_MODEL，未发出真实模型请求。端到端流程由替身模型测试，真实输出质量与模型兼容性仍待接入后验收。
- 无自动语义审校、长篇记忆、自动事实提取、多角色自主群聊、货币金额硬预算、跨版本撤销；不得把这些目标描述为已上线。
- 本轮技术核对：[OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。

## 视觉复核后的结构修正

用户指出首轮实际页面与已批准稿有明显布局偏差。本轮重新按 design-review/light.html 的三栏比例重构 DOM，而非仅调整色值：

- 侧栏 / 正文工作区 / 创作搭档现在为应用框架三个同级网格区域，创作搭档头部与正文头部对齐。
- 去掉顶部重复的作品概览和横向功能导航；真实工具移到侧栏，显示与导出选项收进顶栏菜单。
- 使用接近原稿的圆角应用框架、灰白表面层次、微弱阴影、小型书封和目录双行条目。空待定稿区不占位。
- 对话输入区为统一 composer：引用在上、无独立边框的文本区与控件在同一容器，发送使用箭头图标，聚焦时显示细描边。
- 空对话显示可点击的创作起点，不伪造用户对话和生成内容。有真实 AI 稿件时展示标题、正文片段、待审阅状态和打开草稿按钮。
- 将原稿的表面层次、比例与组件边界应用到实际程序。保留真实数据的正文长度及空状态差异，不通过假数据伪造已接通模型。
- 已实际截图检查桌面与当前窄窗口；桌面侧栏和空对话无多余滚动，窄窗口保留正文 / 对话双栏，侧栏通过菜单展开。
